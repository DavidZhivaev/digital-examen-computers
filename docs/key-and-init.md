# Ключ и установка компьютера

## Что лежит в файле ключа

Файл `de-key.txt` — это **один JWT, подписанный RS256**, и несколько строк
комментария вокруг него. Длина токена около 900 знаков.

Внутри токена зашиты владелец (`login`, `sub`, `role`), момент выдачи и
случайная добавка на 48 байт. Подпись ставится закрытым ключом сайта,
который лежит файлом рядом с остальными секретами прода и наружу не выходит.

Открытую часть сайт отдаёт всем: `GET /api/computers/key/public`. Компьютер
забирает её при установке в `/etc/digital-examen/key-public.pem` и дальше
проверяет подпись сам — **в том числе без интернета**. Проверка написана на
чистом Python (`pylib/de_keys.py`), чтобы на МОС 12 не требовался сторонний
пакет.

### Ключ подписи создаётся один раз, руками

На школьном сервере, рядом с остальными секретами:

```
sudo python3 scripts/make_init_key.py
```

Кладёт `/opt/digital-examen/secrets/screens/init-key.pem` правами 0400 и
владельцем 1000 — так же, как остальные секреты, и так, чтобы его читал
контейнер. В контейнере этот каталог смонтирован **только для чтения**, и
это правильно: если бы сайт создавал ключ на ходу, при каждом перезапуске
появлялся бы новый, и все выданные ключи установки становились бы
непроверяемыми. Поэтому без файла сайт честно отвечает
«Нет ключа подписи ключей установки», а не придумывает его сам.

**Этот файл обязательно включить в резервную копию.**

Сайт хранит только `jti` токена и sha256 от него. Сам токен существует в
одном экземпляре — на флешке.

## Срок и число применений

Срока жизни и предела применений у ключа **нет**. Ключ привязан к личности
владельца, и прежние ограничения только мешали: ставить класс из тридцати
машин приходилось, поглядывая на счётчик, а посреди работы ключ мог
протухнуть.

Ключ гаснет в четырёх случаях:

1. его отозвали кнопкой на сайте;
2. тот же человек **скачал новый ключ** — живым остаётся только последний;
3. владелец **сменил пароль** (или пароль ему сбросили);
4. у владельца забрали право выдавать ключи.

Первые три отражены в учёте: в списке ключей видно, почему ключ погас.
Четвёртый проверяется заново на каждом применении, поэтому в базе ничего не
меняется, а ключ всё равно перестаёт работать.

## Имя файла

Подходит `de-key.txt`, а также то, что получается при повторном скачивании:
`de-key (1).txt`, `de-key (2).txt`, `de-key(1).txt`, `de-key-1.txt`. Регистр
не важен. Если подходящих файлов несколько, берётся самый свежий по времени
изменения.

## Установка

```
sudo sh run.sh
```

В конце установки скрипт просит вставить флешку с ключом и ждёт её. Дальше:

1. компьютер проверяет подпись токена своим экземпляром открытого ключа и
   показывает, чей это ключ;
2. токен уходит на сайт, где проверяется, не отозван ли он, не заменён ли
   новым и есть ли **сейчас** у владельца право ставить компьютеры;
3. спрашиваются номер корпуса, аудитории и компьютера;
4. компьютер регистрируется на сайте, получает имя вида `2k-419-16` и свои
   четыре секрета.

Компьютерный класс заводится сам при регистрации первого компьютера в нём.

## Та же флешка как ключ от sudo

Пока флешка с ключом вставлена, её владелец — и только он — получает `sudo`
на этом компьютере. Вынули флешку — право забирается.

Делает это `bin/de-keywatch`: раз в пять секунд смотрит, есть ли на
подключённом сменном носителе файл с подходящим именем. Подпись проверяется
на месте, и только совпавший с вошедшим владелец идёт на сайт за
подтверждением. Читаются только файлы с известным именем в корне носителя и
на один уровень глубже.

### Что именно можно по этому sudo

Не всё. Прежде `de-keyholders` получали `ALL=(ALL) ALL` с вычетом нескольких
запретов, и полный root обходил эти запреты установкой пакета. Теперь это
**список разрешённого** (`config/sudoers.de-keyholders`):

- наши же инструменты: `de-init`, `de-vault sync|show`, `de-rotate`,
  `de-encrypt status|root-advice`, `de-deps check`, `de-selftest`;
- службы: `systemctl status|start|restart de-*`, `journalctl`;
- железо: `nmcli`, `lpadmin`, `cupsctl`, `lpinfo`, печать;
- посмотреть: `dmesg`, `ip addr|route`, `ss -tulpn`, `lsblk`, `df -h`;
- выключение и перезагрузка.

Пакетных менеджеров, оболочек и редакторов в списке нет намеренно: любой из
них равен полному root. Когда на машине действительно нужен root — это
делается учётной записью администратора школы, а не ключом.

## Список ключей на сайте

Вкладка «Компьютеры → Ключи установки»: кому выдан, работает ли, сколько
применений, где применялся последний раз, и кнопка отзыва. Там же видно
состояние выгрузки для входа без интернета.
