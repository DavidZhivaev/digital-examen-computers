# Классификатор ИИ

Задача одна: ответить **«ИИ или не ИИ»** про страницу, с уверенностью и
цитатой. Классификатор ничего не блокирует. Решение принимает группа
ограничений с галочкой «ИИ автоматически» (`ai_auto`), и спрашивает
классификатор только она, и только после того, как страницу не разобрали
обычные списки.

## Где живёт

На ШС, контейнер `de-ai`, порт 9850 **только внутри docker-сети**: наружу
классификатор не публикуется вообще. Ручки:

```
GET  /health    -> обучена ли модель и как
POST /classify  {host, url, title, text} -> {ai, confidence, quote, reason, ms}
```

Компьютер спрашивает его **через сайт**: `POST /api/computers/device/ai`, с
личным секретом этой машины. Так ни классификатор, ни какой-либо общий на всю
школу секрет наружу не выставлены — у компьютера есть только его собственный
секрет, а право спрашивать проверяется там же, где и всё остальное.

Контейнер ограничен двумя ядрами и 3 ГБ. Ночной контейнер `de-ai-night`
(четыре ядра, 8 ГБ) занимается разметкой и доучиванием.

## Из чего состоит ответ

1. **Домены из `never-block.txt` классификатору не показываются вообще.**
   Это проверяется и на стороне компьютера, и ещё раз в самой службе: госуслуги,
   МЭШ и школьные адреса не попадают в модель даже как текст.
2. **Признаки с весами** (`markers.py`): адрес (`udm=50`, `/completions`,
   `/conversation`), известные домены ИИ, слова на странице («AI Overview»,
   «Нейро», «YandexGPT», «языковая модель»). Сумма веса ≥ 6 — ответ «ИИ» без
   модели: это те случаи, где и так всё ясно, и тратить на них 30–80 мс незачем.
3. **Модель** (`model.py`): `multilingual-e5-small` (250 МБ) даёт вектор по
   строке «домен + заголовок + первые 1200 знаков текста», к вектору
   добавляются пять чисел от признаков, сверху логистическая регрессия.
   Порог — `DE_AI_THRESHOLD`, по умолчанию 0,75.

Пока модель не обучена, служба отвечает только по признакам и честно пишет это
в `reason`. Молчащий или медленный классификатор означает «пропустить»:
закрывать интернет из-за недоступной модели нельзя (`de-policy.ask_ai`,
таймаут `DE_AI_TIMEOUT=2`).

## Почему именно так, а не одна большая модель

Большая модель на восьми ядрах ШС обрабатывает страницу секундами. На 1440
машин это не считается — то же арифметическое ограничение, из-за которого
фильтр живёт на компьютерах, а не на ШС. Поэтому большая модель работает
**ночью** и только:

- размечает спорные страницы (`doubt.jsonl`, уверенность от 0,35 до 0,75);
- отвечает строго объектом JSON, иначе ответ отбрасывается.

Берётся та модель, которая **уже стоит на ШС**: там есть `ollama` с
`qwen3:4b-instruct-2507-q4_K_M` (2,5 ГБ). Качать `Qwen2.5-7B` (4,7 ГБ) и
ставить рядом второй движок незачем. `ollama` слушает только петлю хоста,
поэтому разметка запускается **не в контейнере, а на самом ШС** таймером
`de-ai-label.timer` (01:10, `Nice=19`, `IOSchedulingClass=idle`) — это
дешевле и безопаснее, чем давать контейнеру сеть хоста. Модель меняется
переменной `DE_AI_OLLAMA_MODEL`.

Утром `train.py` доучивает логистическую регрессию на размеченном
(`labelled.jsonl`) и печатает F1 по пяти частям — это и есть проверка, что
модель не стала хуже.

## Разметка и обучение руками

```
# на ШС: разметка идёт на хосте, обучение в контейнере
systemctl start de-ai-label.service && journalctl -u de-ai-label -n 20
docker compose -f /opt/digital-examen/computers/ai/docker-compose.yml \
    exec de-ai-night python3 /usr/local/bin/train.py
```

Файлы лежат в `/data/digital-examen/ai`:

| Файл | Что |
|---|---|
| `doubt.jsonl` | спорные страницы, сложила сама служба |
| `labelled.jsonl` | обучающая выборка (`label` 0 или 1) |
| `doubt-done.jsonl` | что уже отдавали большой модели |
| `classifier.pkl` | обученная логистическая регрессия |
| `classifier.json` | числа последнего обучения |
| `e5-small/` | скачанная модель векторов |
Большая модель для ночной разметки лежит не здесь, а в хранилище `ollama`.

Меньше 40 размеченных страниц — `train.py` отказывается обучаться и так и
говорит.

## Что проверено на боевом ШС (18.10.2026)

Модель `multilingual-e5-small` скачана (466 МБ), обучение и ответы работают:

| Страница | Ответ | Время |
|---|---|---|
| `chatgpt.com` | ИИ, по признакам | 0 мс |
| `uchebnik.mos.ru` | не ИИ, never-block, модели не показана | 0 мс |
| `chat.mistral.ai` (нет в списках) | **ИИ, 0,86, модель** | 47 мс |
| новость про нейросети | не ИИ, 0,36 | 76 мс |
| задачник `sdamgia.ru` | не ИИ, 0,001 | 53 мс |
| `ya.ru` с «Нейро» | спорно, 0,63 — уходит на ночную разметку | 48 мс |

30–80 мс на страницу — как и планировалось.

Ночная разметка проверена вживую: `de-ai-label.service` поднял
`qwen3:4b-instruct-2507` и разметил спорное правильно — Яндекс с «Нейро» это
ИИ (уверенность 0,98), новость про нейросети — не ИИ (0,99). Три страницы с
загрузкой модели заняли 64 с.

**Выборка пока игрушечная.** Чтобы завести обучение, я положил 100
синтетических страниц с пометкой `"by": "синтетика-проверка"` — на них F1
получается 0,97, но это проверка работоспособности, а не качество. Реальная
точность появится, когда наберутся настоящие страницы со школьных машин (это
начнётся вместе с `de-filter`), а синтетику тогда надо выкинуть:

```
grep -v '"by": "синтетика-проверка"' labelled.jsonl > labelled.jsonl.new
```

## Проверка признаков на живых примерах

| Страница | Сумма | Вывод |
|---|---|---|
| `chatgpt.com/c/...` | 11,5 | ИИ без модели |
| Google с `udm=50` | 6,0 | ИИ без модели |
| `ya.ru` с «Нейро» и «YandexGPT» | 3,5 | спорно, решает модель |
| новость про нейросети на `lenta.ru` | 3,0 | спорно, решает модель |
| `uchebnik.mos.ru` | 0 | never-block, модели не показывается |

Последние два — ровно то, зачем нужна модель: по словам они похожи, а по сути
новость про ИИ блокировать нельзя.

## Чего ещё нет

- **Текста страницы пока никто не даёт.** `de-policy` умеет спрашивать
  классификатор, но на вход у него есть только домен и адрес: расшифровки
  трафика ещё нет. Полноценно классификатор заработает вместе с `de-filter`,
  который и даст заголовок и текст.
- Яндекс не проверен со школьного компьютера (с рабочей машины отдаёт капчу).
- Поведенческое обнаружение «переписки с ИИ» по журналу запросов.
