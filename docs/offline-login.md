# Вход без интернета

Войти на компьютер нужно и тогда, когда сайт недоступен: оборвалась связь с
корпусом, лежит ШС, идут работы у провайдера.

## Главное

**Входить без интернета может любой ученик и любой предметник информатики -
и на том компьютере, за которым он никогда раньше не сидел.** Остальные
взрослые входят только при живом интернете: им офлайн не нужен, а лишние
учётки в выгрузке - лишний риск.

Так получилось потому, что проверочное значение считается **из bcrypt-хеша,
который и так лежит у сайта**, а не из пароля в момент входа. Ждать, пока
человек «засветит» пароль на этой машине, больше не нужно.

## Как проверяется пароль, когда данных нет и интернета нет

Данные есть. Нет только пароля и интернета.

**Что готовит сайт.** У сайта есть `password_hash` - bcrypt со стоимостью 12.
Для каждого ученика и предметника информатики он считает:

```
соль  = 16 случайных байт
шаг 1 = scrypt(bcrypt-хеш, соль, n=2^17, r=8, p=1)   → 128 МБ памяти, 0,7 с
шаг 2 = pbkdf2_hmac_sha512(шаг 1, соль, 1 200 000)   → 0,7 с
```

В выгрузку кладётся результат шага 2, соль, и **префикс** bcrypt - алгоритм,
стоимость и соль bcrypt (`$2b$12$<22 знака>`), без самого хеша.

**Что лежит на компьютере.** Запечатанная выгрузка: логин, префикс bcrypt,
соль, параметры, проверочное значение. Паролей нет. Хешей пароля с сайта
**нет** - из проверочного значения bcrypt-хеш не восстановить, значит кража
выгрузки не равна краже боевой базы паролей.

**Что происходит при офлайн-входе.** Человек набирает логин и пароль.
`de-login-auth` не дождался сайта и оставил метку «сайт не ответил». Дальше
`de-offline-auth`:

1. находит строку по логину, берёт префикс bcrypt;
2. считает `bcrypt(пароль, префикс)` - 0,25 с;
3. считает те же два шага, scrypt и pbkdf2;
4. привязывает результат к секрету этого компьютера и сравнивает.

Совпало - пароль тот самый. Замерено: **1,4 с на одну проверку** на рабочей
машине и на `python 3.8`, на школьной будет около двух.

## Почему такую выгрузку нельзя перебрать

Чтобы проверить одну догадку, нужно пройти **всю** цепочку: bcrypt стоимостью
12, затем scrypt на 128 МБ, затем 1 200 000 итераций pbkdf2. Пропустить
нельзя ни один шаг - именно потому, что в выгрузке нет промежуточных
значений.

| Что стоит одна попытка | Сколько |
|---|---|
| процессорное время | ≈1,4 с |
| память | 128 МБ (scrypt не даёт считать на видеокартах массово) |
| попыток в час на ядре | ≈2 500 |

Сверху два замка:

- **привязка к машине.** В выгрузке лежит `HMAC(vault.secret компьютера,
  результат)`. Выгрузка без секрета из `/etc` этой машины не проверяется
  вообще - перебирать нечего.
- **шифрование.** И выгрузка, и секрет лежат в отдельном зашифрованном томе
  LUKS2 (`de-encrypt`), ключ по возможности в TPM. Вынос диска не даёт ни
  выгрузки, ни секрета.

Честный вывод: **стойкость упирается в сам пароль.** Случайный пароль из
восьми знаков с заглавными, строчными и цифрами - это около 2·10¹⁴ вариантов,
то есть 2,8 миллиарда ядро-часов, недостижимо. А «Лето2026» из словаря в
десять тысяч строк падает за четыре часа на одном ядре. Поэтому вместе с этой
схемой на сайте включено **обязательное требование сложности пароля**
(`core/password_rules.py`): не короче восьми знаков, заглавная и строчная
буквы, цифра или особый знак. Без этого требования всё остальное
бессмысленно.

## Что закрывает вход тому, кому нельзя

- **Срок.** Выгрузка, не обновлявшаяся дольше `DE_VAULT_MAX_AGE_DAYS`
  (30 дней), не принимается.
- **Отключённые.** В выгрузку попадает только живая учётка: `is_active`, без
  требования сменить пароль. Отключили человека - он выпадает из выгрузки на
  всех компьютерах в течение получаса.
- **Смена пароля.** У значения хранится отпечаток bcrypt-хеша; сменился
  пароль - сайт пересчитывает значение, и старый пароль офлайн больше не
  работает.
- **Роль.** Ученики - по `DE_ALLOW_ROLES`. Взрослые - только предметники
  информатики, остальных в выгрузке нет.
- **Перебор на месте.** Десять неудач по одному логину закрывают его на
  30 минут.

## Как это работает в хозяйстве

Считать значения дорого (≈1,4 с на человека), поэтому они лежат в базе
(`computers_offline`) и пересчитываются только когда сменился пароль или
человека только что допустили. Пересчёт идёт порциями:

```
POST /api/computers/device/offline/refresh  {"limit": 100}
```

На ШС это делает таймер `de-offline-refresh.timer`. Состояние видно на сайте:
`GET /api/computers/offline` - сколько учёток готово.

Компьютер забирает выгрузку **частями**: говорит, на какой момент у него
данные, и получает только изменения (`since`), иначе 1440 машин тянули бы
полную выгрузку каждые полчаса. Полная выгрузка на 3000 учёток - около 1 МБ,
дальше идут только изменения.

## Проверить руками

```
de-vault show          # сколько учёток, свежая ли выгрузка
de-vault sync          # забрать изменения
grep de-vault /var/log/digital-examen-computers.log
```
