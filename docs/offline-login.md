# Вход без интернета

Войти на компьютер нужно и тогда, когда сайт недоступен: оборвалась связь с
корпусом, лежит ШС, идут работы у провайдера. Поэтому на каждом компьютере
лежит выгрузка учёток, по которой можно проверить пароль на месте.

## Как это работает по шагам

1. Человек входит **при живом интернете**. В этот момент пароль есть в
   открытом виде ровно у одного процесса — `de-login-auth`. Он считает от
   пароля медленную функцию и отдаёт сайту только её результат
   (`/api/computers/device/offline/push`). Пароля и его хеша с сайта в
   выгрузке нет никогда.
2. Сайт хранит это значение в `computers_offline`.
3. Раз в 30 минут (`de-vault-sync.timer`) компьютер забирает выгрузку
   (`/api/computers/device/offline/bundle`) и кладёт её в
   `/var/lib/digital-examen/vault/bundle.de`.
4. Нет интернета — `de-login-auth` отвечает «сайт недоступен» и пишет это в
   `/run/digital-examen/last-attempt.json`. Следом в PAM стоит
   `de-offline-auth`: он срабатывает **только** если сайт действительно не
   ответил не больше двух минут назад, и проверяет пароль по выгрузке.
5. Дальше всё как при обычном входе: временный пользователь, tmpfs-домашняя
   папка, песочница, запись экрана. Сеанс помечается как офлайновый
   (`/run/digital-examen/offline-<логин>`), и `de-report` сообщит о нём сайту,
   когда связь вернётся.

## Медленная функция

```
промежуточное = scrypt(пароль, соль, n=2^16, r=8, p=1, 64 байта)
проверочное  = pbkdf2_hmac_sha512(промежуточное, соль, 1 200 000, 32 байта)
```

Замер на рабочей машине: **1,0 с на одну проверку** (scrypt 0,32 с + pbkdf2
0,76 с), памяти 64 МБ. На школьном компьютере будет медленнее, около 1,5–2 с —
это цена одного входа без интернета и она терпимая.

Для перебора это значит: 1440 попыток в час на одном ядре. Пароль из восьми
знаков с буквами и цифрами перебрать по такой выгрузке нельзя за разумное
время, а по словарю из тысячи частых паролей — примерно 17 минут на одну
учётку. Поэтому к медленной функции добавлены ещё два замка.

## Замок первый: привязка к компьютеру

В выгрузке лежит не результат медленной функции, а

```
HMAC-SHA256(ключ = vault.secret этого компьютера, результат)
```

`vault.secret` выдаётся при постановке на учёт, свой на каждую машину, лежит
в `/etc/digital-examen/vault.secret` с правами `0600` у root. Выгрузка,
скопированная на другой компьютер или на домашний ноутбук, **не проверяется
вообще**: без ключа подобранный пароль не с чем сверить.

## Замок второй: выгрузка запечатана

Файл `bundle.de` зашифрован и подписан тем же ключом (ключевой поток из
HMAC-SHA256, подпись HMAC-SHA256, шифрование до подписи, всё на стандартной
библиотеке — ни на МОС 12, ни на ШС не нужен сторонний пакет). Подменить в
выгрузке чужой логин или добавить свою учётку нельзя: подпись не сойдётся.

Чего это **не** даёт: если украли компьютер целиком, вместе с `/etc`, то ключ
у вора есть, и остаётся только стоимость медленной функции. Поэтому в
`docs/` отдельной строкой: системный диск школьного компьютера имеет смысл
держать под LUKS, а выгрузка живёт не дольше месяца (ниже).

## Что закрывает вход тому, кому нельзя

- **Срок.** Выгрузка старше `DE_VAULT_MAX_AGE_DAYS` (30 дней) не принимается.
  Компьютер, месяц простоявший без сети, офлайн-вход не разрешит.
- **Ушедшие.** В выгрузку попадает только живая учётка: `is_active`, без
  требования сменить пароль. Отключили человека на сайте — через полчаса его
  нет в выгрузке на всех компьютерах.
- **Смена пароля.** Проверочное значение старше последней смены пароля в
  выгрузку не попадает. Значит, по старому паролю офлайн не войти, а по
  новому можно будет после первого входа при живом интернете.
- **Перебор на месте.** Десять неудачных офлайн-попыток по одному логину
  закрывают этот логин на 30 минут (`DE_VAULT_MAX_TRIES`,
  `DE_VAULT_LOCK_MINUTES`). Счётчик лежит в
  `/var/lib/digital-examen/vault/attempts.json`.
- **Роль.** Как и онлайн, роль проверяется по `DE_ALLOW_ROLES`.

## Первый вход на новом компьютере

Пока человек ни разу не входил при живом интернете, его проверочного значения
нет ни у сайта, ни в выгрузке, и офлайн-вход для него невозможен. Это не
ошибка, а свойство схемы: пароль знает только сайт, и без пароля проверочное
значение не из чего посчитать.

Поэтому `de-init` сразу после постановки на учёт делает `de-vault sync`, а
выгрузка приходит на компьютер со значениями **всех**, кто входил на любом
компьютере школы за последние 120 дней (`DE_OFFLINE_BUNDLE_DAYS`).

## Проверить руками

```
de-vault show          # есть ли ключ, сколько учёток, свежая ли выгрузка
de-vault sync          # забрать выгрузку заново
journalctl -u de-vault-sync
grep de-vault /var/log/digital-examen-computers.log
```

## Что ещё не сделано

- Офлайн-вход не знает про ограничения интернета, которые завели, пока сети
  не было: он берёт последнюю политику из `/run/digital-examen/policy.json`.
  Это безопасно (интернета всё равно нет), но после возврата связи политику
  надо перечитать — это делает `de-agent` по команде `policy`.
- На сайте нет экрана «сколько учёток выгружено и когда». Сейчас это видно
  только через `de-vault show` на компьютере.
