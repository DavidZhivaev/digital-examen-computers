# Секреты компьютеров и ключ администратора

## Было и стало

Раньше на всю школу был один секрет прокси и один секрет команд. Это значило,
что компьютер своим секретом мог:

- прислать кадры от имени соседней машины;
- **прочитать экран** другого ученика ручкой `/shot/<компьютер>`;
- забрать себе чужие команды из `/commands`.

Теперь у каждой машины свои четыре секрета, по 32 случайных байта:

| Файл | Для чего |
|---|---|
| `/etc/digital-examen/proxy.secret` | разговор с сайтом: вход, журнал, сеансы |
| `/etc/digital-examen/command.secret` | команды с сайта |
| `/etc/digital-examen/screen.secret` | кадры экрана и опрос команд у приёмника |
| `/etc/digital-examen/vault.secret` | выгрузка учёток для входа без интернета |

Все четыре — `0600`, владелец root, выдаёт их сайт при постановке на учёт и
записывает в базу (`computers_secrets`). Экранный секрет сайт тут же приносит
приёмнику кадров (`POST /secrets`), иначе кадры приниматься не будут.

## Что теперь нельзя

Проверено на приёмнике вживую (`DE_ALLOW_SHARED_SECRET=0`):

```
кадр своим секретом            -> ok
кадр секретом соседа           -> 403
кадр общим секретом            -> 403
чужой экран секретом соседа    -> 403
команды чужому компьютеру      -> 403
команды себе                   -> ok
```

Ручки `/shot`, `/record`, `/watch`, `/power`, `/console`, `/policy` требуют
**административного** секрета, который есть только у сайта. Компьютер ими
воспользоваться не может вообще.

## Переходный период

`DE_ALLOW_SHARED_SECRET=1` (по умолчанию и на приёмнике, и на сайте) означает,
что общий секрет пока принимается: иначе обновление выбросило бы из системы
все машины сразу. Порядок такой:

1. Обновить сайт и приёмник.
2. Переставить компьютеры с ключом (`sudo sh setup.sh` или `de-init`) — каждый
   получит свои секреты.
3. Когда переставлены все, выставить `DE_ALLOW_SHARED_SECRET=0` на приёмнике и
   на сайте и перезапустить их. С этого момента общий секрет не работает.

## Ключ администратора при установке

Без ключа компьютер на учёт **не ставится**. Ключ — файл `de-key.txt` в корне
флешки, его выдаёт сайт (Компьютеры → «Скачать ключ») администраторам
информатики и администраторам школы.

`de-init` ждёт флешку, читает только этот файл по известному имени, и отдаёт
сайту отпечаток и секрет ключа. Сайт **каждый раз заново**:

- ищет ключ в `computers_keys`, проверяет, что он не отозван;
- находит владельца и проверяет, что тот активен и у него **сейчас** есть
  право выдавать ключи.

Забрали у человека администрирование информатики — его флешка в тот же момент
перестаёт ставить компьютеры. Отметка о применении ключа пишется в
`last_used_at`.

Та же флешка во время сеанса по-прежнему выдаёт владельцу `sudo` на этом
компьютере (`de-keywatch`), вынули — забирает.

## Запись экрана и sudo

Владелец ключа получает полный `sudo`, но правило
`/etc/sudoers.d/de-keyholders` запрещает ему `systemctl stop|disable|mask|kill
de-screen*`. Это замедляет случайное выключение записи, но не делает его
невозможным: полный root всегда может остановить службу. Что остаётся честной
защитой:

- служба стоит на `Restart=always`, перезапускается через 5 с;
- «включён ли компьютер» сайт определяет **по идущим кадрам**, а не по
  сердцебиению, поэтому пауза в записи видна на сайте сразу;
- каждый запуск пишет в журнал `запись экрана запущена`, то есть перерыв
  остаётся в логах.
