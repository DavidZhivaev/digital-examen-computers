# Диагностика каталога МЭШ — 28.11.2026

Проверка выполнена браузером Chromium от Linux-пользователя `test`.
После нажатия «Каталог» на `uchebnik.mos.ru` интерфейс открывает `/catalogue`
и многократно запрашивает `/nsi/api/v3/structure/subject-program`.

В журнале действующего фильтра обнаружен ответ 403 с причиной «Триггер-фраза»:
группа «Блокировка ИИ», фраза «Искусственный интеллект». Аналогичное срабатывание
зафиксировано на `school.mos.ru/v1/allSubsystems/`. Это применение настроенного
школьного правила к справочнику, а не таймаут транспортного реле.

Правило, охват проверки содержимого и исключения доменов не изменены.
Вопрос корректности правила на образовательных справочниках следует передать
ответственному администратору школы. Его нельзя исправить отключением проверки
JSON или добавлением обхода блокировки.

Исправление протокола: если заблокирован JSON API, инспектор сохраняет статус
403 и возвращает `application/problem+json`, а не HTML-документ вместо JSON.
Данные заблокированного ответа не передаются. Для обычной HTML-навигации
сохраняется школьная страница блокировки. Это устраняет ошибку формата ответа,
но не делает запрещённый справочник доступным и не гарантирует снятие индикатора
загрузки в стороннем интерфейсе.

Тип содержимого виден только после получения HTTPS-заголовков. Выключать TLS-
перехват по ещё неизвестному MIME-типу отдельного запроса невозможно, особенно
при нескольких типах ресурсов в одном HTTP/2-соединении. Анализ тела и TLS-
расшифровка — разные этапы. Существующие проверки HTML и остальных настроенных
типов сохранены, чтобы не ослаблять школьные ограничения.
