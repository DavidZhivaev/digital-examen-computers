# digital-examen-computers

Настройка школьного компьютера под М ОС 12 для системы «Цифровой экзамен».

Ученик вводит на экране входа **свой логин и пароль с сайта**. Компьютер
спрашивает сайт, и если тот подтвердил — локальный пользователь создаётся на
месте. При выходе из сеанса и при выключении компьютера этот пользователь
удаляется вместе со всем содержимым домашней папки.

## Установка

Ничего настраивать заранее не нужно. На чистом компьютере:

```
git clone https://github.com/DavidZhivaev/digital-examen-computers.git
cd digital-examen-computers
sudo sh run.sh
```

`run.sh` сам проверяет и доставляет из интернета всё, чем мы пользуемся
(ffmpeg, ImageMagick, nftables, cryptsetup, bcrypt и остальное), включает
шифрование секретов и записей и только потом ставит систему. Подробно:
[docs/install.md](docs/install.md).

Скрипт попросит **флешку с ключом администратора** (`de-key.txt`, скачивается
на сайте: Компьютеры → «Скачать ключ»), спросит **номер корпуса, номер
аудитории и номер компьютера**,
проверит на сайте, что это место ещё не занято другой машиной, получит **свои собственные
секреты** (у каждого компьютера они свои), настроит всё остальное и **перезагрузит компьютер**. После
перезагрузки сразу появляется экран входа, где ученик вводит логин и пароль
с сайта.

Сайт системы — `https://ex.1580.ru`. Другого адреса вписывать не нужно.

Репозиторий при установке переносится в `/opt/digital-examen-computers`,
откуда компьютер **сам проверяет обновления раз в 15 минут**
(`de-update.timer`): если в `main` появились новые коммиты, они подтягиваются
и переустановка проходит сама, без участия человека.

## Что делает setup.sh

- кладёт скрипты в `/usr/local/sbin`
- создаёт `/etc/digital-examen/computers.conf` из примера
- вписывает в `DE_PROTECTED_USERS` **всех пользователей, которые уже есть на
  компьютере** — их система не трогает никогда
- создаёт системную группу `de-students`
- запрещает группе ssh (`/etc/ssh/sshd_config.d/90-digital-examen.conf`)
- включает на экране входа поля «логин» и «пароль»
  (`/etc/sddm.conf.d/90-digital-examen.conf`)
- добавляет хук в `/etc/pam.d/sddm`, сохраняя исходник в
  `/etc/pam.d/sddm.before-digital-examen`
- включает службу `de-cleanup.service`

## Как работает вход

1. Экран входа показывает поля логина и пароля. Это включается строкой
   `MinimumUid=10000000` в конфиге SDDM: список пользователей становится
   пустым, и тема `mos-auth` сама переключается на ручной ввод. Саму тему
   править не нужно.
2. `pam_exec` вызывает `de-login-auth` **до** `system-auth`:

   ```
   auth [success=done default=ignore] pam_exec.so expose_authtok quiet /usr/local/sbin/de-login-auth
   ```

3. `de-login-auth` берёт логин из `PAM_USER`, пароль со stdin и:
   - молча уступает обычному PAM, если логин в `DE_PROTECTED_USERS`, или такой
     пользователь уже есть на компьютере сам по себе, или логин не подходит под
     разрешённый шаблон;
   - иначе получает задачу proof-of-work с `/auth/pow/challenge`, решает её и
     отправляет логин с паролем на `/auth/login`;
   - при успехе проверяет роль из токена, создаёт пользователя `useradd` с
     группой `de-students`, ставит пароль и пишет запись в
     `/var/lib/digital-examen/users/<логин>`.
4. Код возврата 0 завершает стадию `auth` успехом (`success=done`). Любой
   другой код — это `default=ignore`, дальше работает обычный `pam_unix`,
   который для несуществующего пользователя откажет.

## Как работает удаление

- `de-session` на закрытие сеанса вызывает `de-cleanup <логин>`, если
  `DE_WIPE_ON_LOGOUT=1` (по умолчанию да).
- `de-cleanup.service` вызывает `de-cleanup` на старте системы и на выключении.
  Старт нужен на случай, если компьютер выключили из розетки.
- `de-cleanup` удаляет только тех, у кого есть запись в
  `/var/lib/digital-examen/users` или основная группа `de-students`, и никогда
  не трогает `DE_PROTECTED_USERS`.

## Логины и регистр

На сайте логины выдаются в смешанном регистре — `ZhivaevDA`. Ученик за
компьютером набирает как получится, поэтому:

- UNIX-пользователь всегда создаётся в нижнем регистре: `zhivaevda`;
- если набрали иначе (`ZhivaevDA`, `ZHIVAEVDA`), дополнительно создаётся
  **второе имя на тот же UID** через `useradd --non-unique`. Это одна учётная
  запись с одной домашней папкой, просто доступная под двумя именами;
- на сайт логин всегда уходит в нижнем регистре, а сайт ищет его без учёта
  регистра (`login__iexact` в `auth/routers.py`).

Требование к самим логинам: в нижнем регистре логин должен подходить под
`^[a-z][a-z0-9_-]{2,31}$`. Логины с точками и русскими буквами на компьютер не
пустят — такой вход уступит обычному PAM и закончится отказом.

## Песочница и прокси

У каждого вошедшего ученика — своё сетевое пространство имён `de-<логин>`, где
нет ни физической сетевой карты, ни IPv6, ни DNS. Единственный доступный адрес —
его собственный экземпляр релея, который подставляет его логин и школьный секрет
и передаёт запрос прокси на ШС. Домашняя папка — tmpfs, на диск не пишется
ничего.

Ограничения свои на каждого: сначала личная политика ученика, потом политика его
класса, и поверх всего белый список школы.

`de-box` даёт ученику **root в песочнице** на `systemd-nspawn` с overlayfs в
памяти. Проверено на живой системе, что этот root не может ни удалить маршрут, ни
добавить интерфейс, ни сбросить правила фильтра — ядро отвечает
`Operation not permitted`, потому что пространством имён владеет root хоста. Свой
namespace создать можно, но он пустой и выхода в сеть не даёт.

Разбор целиком, вместе с тем, почему прежняя схема на `iptables` из mos12
обходилась, — [docs/proxy-and-sandbox.md](docs/proxy-and-sandbox.md).

Адрес прокси и адрес сайта указывают на **ШС**, а не на VPS, поэтому смена VPS
ничего не ломает.

## Запись экрана

`de-screen` режет экран на тайлы 80×80, считает `crc32` каждого и отправляет на
ШС только изменившиеся; при большой доле изменений — полный кадр. На спокойном
экране кадр стоит 0,7–2,5 КБ вместо 25–54 КБ. Принимает
[screens/receiver.py](screens/receiver.py), который ничего не перекодирует.

Интервал не задан жёстко: движок делит размер последних кадров на бюджет
(`DE_SCREEN_BUDGET_KBITS`) и подбирает паузу сам. На спокойном экране это **раз в
секунду**, при активной работе разжимается до 10–16 секунд. Отдельно уходит
миниатюра 320×180 (3,3 КБ) для менюшки со всеми компьютерами.

`de-agent` держит длинный опрос команд, поэтому живой режим включается сразу, а
не со следующим кадром. На этом же канале потом блокировка экрана, сообщения и
удалённое управление.

Все соединения исходящие, от компьютера к ШС, поэтому схема работает при
компьютерах в разных подсетях и не требует открытых портов на компьютерах.

## Вход без интернета

Если сайт недоступен, вход всё равно проходит: пароль проверяется по выгрузке
учёток, которая лежит на компьютере. Войти может **любой ученик и любой
предметник информатики, даже если за этим компьютером он никогда не сидел** —
проверочное значение считается из bcrypt-хеша, который и так есть у сайта.
Одна попытка стоит bcrypt + scrypt на 128 МБ + 1 200 000 итераций pbkdf2,
замерено 1,4 с; значение привязано к секрету именно этой машины, выгрузка
живёт 30 дней, десять неудач закрывают логин на 30 минут.

```
de-vault show    # есть ли выгрузка и свежая ли она
de-vault sync    # забрать заново
```

Подробно: [docs/offline-login.md](docs/offline-login.md).

## Секреты и ключ администратора

У каждого компьютера свои четыре секрета (`proxy`, `command`, `screen`,
`vault`), выдаёт их сайт по ключу администратора при постановке на учёт.
Компьютер больше не может ни прислать кадры от имени соседа, ни прочитать его
экран. Подробно: [docs/secrets-and-keys.md](docs/secrets-and-keys.md).

## Классификатор ИИ

Служба `ai/` на ШС отвечает «ИИ или не ИИ» с уверенностью и цитатой и ничего
не блокирует сама. Признаки с весами плюс `multilingual-e5-small` с
логистической регрессией; ночью `Qwen2.5-7B` размечает спорные страницы и
модель доучивается. Подробно: [docs/ai-classifier.md](docs/ai-classifier.md).

## Шифрование диска

Секреты, выгрузка учёток, очередь кадров и состояние сеансов лежат в
отдельном томе LUKS2, который создаётся при установке. Ключ по возможности
запечатывается в TPM, тогда на диске его нет вообще. Подробно:
[docs/disk-encryption.md](docs/disk-encryption.md).

```
de-encrypt status
```

## Проверка после установки

```
grep digital-examen /etc/pam.d/sddm
systemctl status de-cleanup.service
tail -f /var/log/digital-examen-computers.log
```

Откатить правку PAM:

```
cp /etc/pam.d/sddm.before-digital-examen /etc/pam.d/sddm
```

## Команды с сайта

`de-agent` держит длинный опрос и выполняет команды: сообщение на экран,
выключение и перезагрузка, выход из сеанса, переключение в живой режим и
произвольная команда консоли. Результат уходит обратно на ШС, поэтому учитель
может послать команду на весь кабинет и получить ответ с каждого компьютера.
На сайте это модуль `fleet`: инвентарь компьютеров, пакеты команд и выгрузка
ответов в Excel.
